The library and the test runner

One idea. With the library, you open and close the browser. The test runner does that for you.

Start with a normal day

You can drive a car yourself. You pick up the keys, you drive, you park, you lock the doors.

A driving exam uses the same car. Someone else starts the session, watches one task, and writes pass or fail. The library is the keys. The test runner is the examiner.

New words

library
The playwright package. Your script calls chromium.launch() to start the browser, and browser.close() to stop it.
runner
The @playwright/test package. You describe a check. The runner starts the browser, runs the check, and closes the browser.
import
Pull named tools out of a package. The two files below import from different packages.
await
Pause this one function until that step finishes. The function is marked async so await is allowed.
page
One browser tab. newPage() opens one. goto opens an address in it. title() reads the document title.
headless
The usual way launch() starts Chromium: no window on the screen.
test
One named check. The sentence in quotes is what the report prints.
=>
A short way to write a function. async ({ page }) => is the function the runner will call.
{ page }
The runner hands you a tab it already opened. A fixture is a tool the runner sets up for you. page is the fixture you use here.
expect
A check. toHaveTitle waits until the tab’s title matches that text. If it never matches, the test fails.

The steps, before any program

Library script. You hold the keys.

  1. Start Chromium.
  2. Open a tab and go to https://example.com.
  3. Print the title.
  4. Close the browser.

Test. The examiner holds the keys.

  1. Name one fact: the title is Example Domain.
  2. The runner gives you a tab. Open https://example.com.
  3. Expect the title to be Example Domain. The runner closes the browser afterward.

The same steps, written as a program

The first file is the keys. Run it with node script.mjs. The second file is the exam. Run it with npx playwright test. Same address. Different person starts the car.

What each line is saying

  1. const browser = await chromium.launch();Library style. You start Chromium. No window appears, because headless is the usual setting.
  2. await browser.close();You stop it. Skip this line and the browser program keeps running.
  3. import { test, expect } from "@playwright/test";Runner style. The runner creates the tab and closes the browser. This file does not import chromium.
  4. test("title is Example Domain", async ({ page }) => {Name one check. { page } takes the tab the runner already opened.
  5. await expect(page).toHaveTitle("Example Domain");The title should become that text. A match passes. A title that never matches fails.

Try it

Turn the checkbox on and off. Watch which side leaves a browser open.

Practice. The box means the library script forgot to close the browser.

Easy to mix up

  • chromium.launch inside a test opens a second browser. The runner already started one and will not track the extra.
  • goto and close need await. The next line otherwise runs while the browser is still working.
  • A .spec.js file belongs to the runner. node runs a library script such as script.mjs.

Remember

The library means you launch and you close. The runner means you write test and expect, and it owns the browser. Repeatable checks use the runner.
