The library and the test runner

The idea

There are two ways to use the same browser powers. The library (playwright) is for a script: you launch, you close, you decide what to print. The runner (@playwright/test) is for checks: you write test(...), you receive a page, you expect something, and the runner collects pass, fail, retries, and a report.

Use the runner for anything you want to repeat and trust. Use the library for a one-off tool, such as saving a login or scraping a page you are allowed to read. This course teaches the runner as the default and shows the library where the launch itself is the lesson.

Why it matters

Copying a library script into a test file, or a test into a plain script, fails in a confusing way. The imports differ. The runner already launched the browser for you. A library script has to launch it.

A picture to hold

A car you drive yourself, versus a driving exam. The car is the same. In the exam, someone else starts the session, watches each task, and writes pass or fail. The runner is the examiner. The library is the car keys.

Example Domain

Line by line

  1. const browser = await chromium.launch();Library style. You start Chromium. Headless is the default, so no window appears.
  2. await browser.close();You also stop it. Forgetting close leaves a browser process running.
  3. import { test, expect } from "@playwright/test";Runner style. You do not import chromium here. The runner creates the page and closes it.
  4. test("title is Example Domain", async ({ page }) => {Declare one test. The name is what the report prints. { page } pulls the page fixture out of the argument. A fixture is a tool the runner sets up for you.
  5. await expect(page).toHaveTitle("Example Domain");An assertion. If the title never becomes that string, the test fails. If it does, the test passes.

Try it yourself

Run the library script and the test. Then remove await browser.close() from the script, run it, and notice a Chromium process still around. Put close back. In the test, change the expected title to "Wrong", run npx playwright test, read the failure, and put the title back.

Common mistakes

  • Calling chromium.launch inside a test. The runner already did the launch. You would be opening a second browser the runner does not track.
  • Forgetting await on goto or close. The process moves on while the browser is still working.
  • Naming every file .spec.js and also trying to run it with plain node. Spec files are for the runner.

Recap

The library means you launch and close. The runner means you write test and expect, and it owns the browser. Prefer the runner for repeatable checks.
