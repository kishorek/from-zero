Saving a login with storage state

One idea. Log in once, save the ticket, and hand that ticket to the next visit.

The idea

Logging in through the form on every test is slow, and it pounds the login service. Playwright can save a context’s cookies and local storage to a JSON file: await context.storageState({ path: "auth.json" }). Later, a context created with storageState: "auth.json" starts already logged in.

In the runner, put that setting in use for a project, or on a single test.use. Produce the file in a setup step you control. Treat auth.json as a secret. Do not commit it.

Why it matters

A suite of twenty tests should not mean twenty logins. One login, saved, gives each fresh context the same keys. The tests stay isolated from each other’s clicks, and they share authentication on purpose.

A picture to hold

A coat-check ticket, the same picture as environment variables, now for a browser profile. You check the coat once (the login). Each new guest room is handed a copy of the ticket at the door (storageState). When the ticket expires, you check the coat again. You do not photocopy the ticket into a public photo album.

A small example

This library script shows the save and the reuse with example.com, which does not actually log in. The mechanics are the same when the cookies come from a real login on a site you are allowed to test. Replace the goto with your login steps when you have them.

Line by line

  1. await context.storageState({ path: "auth.json" });Write cookies and local storage for this context. The file is JSON.
  2. await again.newContext({ storageState: "auth.json" });A new context starts from that file. It does not share a live connection with the old context. It shares the saved snapshot.
  3. console.log("reopened", await page2.title());Proof the second browser could open a page. On a real app you would assert a heading that only a signed-in person sees.

Try it yourself

Log in, start a new visit, then throw the ticket away and visit again.

Demo. The ticket is the saved storage state. It is not the live room.

Common mistakes

  • Committing auth.json. It is a key to an account.
  • Saving storage in the middle of a test and expecting other workers to see it instantly. Generate it in setup, before the tests that need it.
  • Reusing one context for every test so you can “stay logged in.” You lose isolation. Reuse the snapshot, not the live context.

Recap

storageState writes a context’s cookies and storage to JSON. New contexts can start from that file. Keep the file out of git.
