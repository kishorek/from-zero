Saving a login with storage state

One idea. Log in once, save the ticket, and hand that ticket to the next visit.

Start with a normal day

Noor signs in on a website. The site stores a small ticket in the browser so later pages still know her.

She saves a copy of that ticket. Her next visit starts by handing the copy over.

New words

import, await, const, and page mean the same as before. This file is a script, save-state.mjs, so you run it with node.

chromium.launch
Open the Chromium browser. Chrome is in that same family.
context
One session inside the browser. It holds the tabs and the cookies. newContext starts one. newPage opens a tab. goto opens an address in that tab.
cookie
A small note the site stores so it can remember a visit. Local storage is other notes the site stores for itself.
storageState
A saved copy of those notes, written as JSON text. auth.json is the file. The next newContext can start from that file.
close
Quit the browser. The title is the name of the page, shown on the tab.

The steps, before any program

  1. Open a browser, a session, and a page on example.com.
  2. Save that session’s cookies and site notes to a file.
  3. Close the browser.
  4. Open a new session from the file and visit the page again.
  5. Show the page title.

The program only writes those steps down.

The same steps, written as a program

Read the steps once more. The box below is those same steps. The site is example.com, which has no login form. After a real login, the save and the second visit work the same way.

What you should see
reopened Example Domain

What each line is saying

  1. const browser = await chromium.launch();Open a Chromium browser. The next lines make a session and a tab inside it.
  2. await page.goto("https://example.com");Open example.com in that session. This visit is the one that gets saved.
  3. await context.storageState({ path: "auth.json" });Write the session’s cookies and local storage into auth.json. The file is a copy you can reuse.
  4. const returning = await again.newContext({ storageState: "auth.json" });Open a new session that starts from that file. It receives the saved cookies and notes.
  5. console.log("reopened", await page2.title());Show the title of the page opened from the saved session. Here the title is Example Domain.

Try it

Press Log in and save a ticket, then New visit. Then press Throw the ticket away and visit again.

Practice. Save a ticket, start a new visit, then throw the ticket away.

Easy to mix up

  • The file auth.json can sign a person in. Keep it out of a shared project.
  • Create the file in a setup step, before the tests that read it.
  • Each new visit can start from the saved file. Each visit still gets its own session.

Remember

storageState saves cookies and local storage to a file, and a new session can start from that file. Keep the file private, and use a site you are allowed to test.
