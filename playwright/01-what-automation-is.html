What browser automation is

One idea. Browser automation is a list of actions a program performs in a browser.

The idea

Browser automation means a program uses a web browser the way a person would. It opens an address, waits for the page, clicks a link, types into a box, and reads the result.

The program does not become the page. It stands outside the page and drives the browser. That is different from JavaScript that lives inside the page, and different from fetch, which only receives the document the server sent.

Why it matters

Some things worth checking only exist after the page’s own JavaScript runs: a button that appears, a menu that opens, a message that arrives late. fetch never sees those. A browser, driven by a script, does.

A picture to hold

A very fast assistant who only follows the card you wrote. The assistant can use the mouse and read the screen. The assistant does not guess that you meant a different button with a similar name. The card is the whole job.

Try it yourself

Add a click step after the read step and before close. Then run.

Practice. Order matters. Open, read, click, close.

Common mistakes

  • Describing the goal (“make sure the site works”) and calling that a script. Automation needs the actions.
  • Assuming fetch and a browser see the same thing. fetch sees the response. A browser also runs the page.
  • Pointing an assistant at a site whose owner did not agree to automation. Permission is part of the task.

Recap

Browser automation is a program using a browser: open, act, read, close. The script is a precise list. It stands outside the page.
