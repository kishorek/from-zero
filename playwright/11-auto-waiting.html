Auto-waiting

One idea. Wait until the button is ready. Do not guess a number of seconds.

The idea

Before Playwright clicks, it checks that the element is attached to the page, visible, stable (not mid-animation), able to receive events, and, where it applies, enabled. If not, it waits and tries again until the timeout.

Assertions such as toBeVisible and toHaveText retry too. A fixed pause does not. page.waitForTimeout exists for debugging a single run. Playwright’s documentation is plain: do not put it in tests you trust. It passes on your laptop and fails when the pause was a little short.

Why it matters

The old pattern was “sleep two seconds, then click.” It is the main source of flaky tests, tests that sometimes pass. Auto-waiting removes the pause and names the condition you actually needed.

A picture to hold

Waiting until the kettle boils, instead of staring at the clock for a number you guessed. The boil is the condition. Five minutes is a guess. Guesses are too long on good days and too short on bad ones.

A small example

Line by line

  1. await page.setContent(`Replace the document with HTML you wrote. Useful for learning a behavior without depending on a website.
  2. <button id="save" hidden>Save</button>The button starts hidden. A locator will not click a hidden button.
  3. setTimeout(() => {The page’s own JavaScript reveals the button 300 milliseconds later. This setTimeout is inside the page, not a sleep in the test.
  4. await page.getByRole("button", { name: "Save" }).click();This line waits until the button is a real, visible, stable click target, then clicks. No pause is written in the test.

Try it yourself

Load the page. Click when ready succeeds. The short fixed wait misses if you press it too soon.

Demo. The Save button appears after about a second.

Common mistakes

  • Adding waitForTimeout whenever a test fails once. Find the fact you should have waited for, and assert it.
  • Waiting for networkidle before every click. Auto-waiting on the action is already the wait.
  • Catching a timeout and ignoring it. A timeout is the test telling you the condition never arrived.

Recap

Clicks and web assertions retry until the element is ready or time runs out. Write the condition. Leave fixed sleeps out of tests.
