Debugging a failing test

One idea. Read the expected line and the received line. Change one thing.

The idea

When a test fails, the runner prints the assertion, the expected value, the received value, and a call log of the actions it took. Read that before you change code. Then open the HTML report.

For a live look, npx playwright test --debug pauses with the inspector. npx playwright test --ui opens UI mode, where you can watch a test and time-travel through actions. Use these to gather one fact. Then stop the debugger and change one thing.

The flow below is a complete check of example.com: open, assert the heading, follow “Learn more,” assert the new host. It is the shape of a real script. When a step fails, the failure names the step.

Why it matters

You now have every piece this course set out to give you: a program, JavaScript, and a browser under test. Debugging is how that skill stays honest. The page is allowed to be wrong. The test is also allowed to be wrong. The evidence decides which.

A picture to hold

The same backwards walk from the debugging lesson, now with a camera. The call log is the walk. The trace is the camera. UI mode is you standing in the hallway. You still change one thing at a time.

A small example

Commands worth remembering: npx playwright test --debug pauses on this test. npx playwright test --ui opens the watcher. npx playwright show-report opens the last HTML report. A failure’s call log lists each action and why it waited.

Line by line

  1. await page.goto("https://example.com");Step 1. If this times out, the problem is the network or the address, not the heading.
  2. const heading = page.getByRole("heading", { level: 1 });A locator variable. Nothing is fetched yet. The search happens when you assert or act.
  3. await expect(heading).toHaveText("Example Domain");Step 2. On failure you get the text Playwright actually saw, including a note when the locator matched nothing.
  4. await page.getByRole("link", { name: "Learn more" }).click();Step 3. Auto-waiting applies. If two links share the name, the error says the locator matched two elements.
  5. await expect(page).toHaveURL(/iana\.org/);Step 4. The address must contain iana.org. A wrong click fails here with the URL you did reach.

Try it yourself

Run the failing check. Change the received text to Example Domain and run again.

Demo. Expected is Example Domain. Received starts out wrong on purpose.

Common mistakes

  • Rewriting locators before reading which step failed. The log already narrowed it down.
  • Leaving .only on a test. test.only runs that test and skips the rest. Fine for an afternoon. Surprising tomorrow. The config can set forbidOnly so CI rejects it.
  • Fixing a product bug and a test bug in the same edit. You will not know which one matched the evidence.

Recap

Read the expectation and the call log. Open the trace or UI mode when you need to see the page. Change one thing. A full flow is still just ordered steps with assertions between them.
