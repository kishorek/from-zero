Debugging a failing test

One idea. Read the expected line and the received line, then change one thing.

Start with a normal day

Ben runs a check on a website, and the check fails. The result says the heading should be Example Domain, while the page showed other words.

He changes one thing and runs the check again.

New words

import, test, expect, await, page, and getByRole mean the same as before.

goto
Open an address. The first step opens https://example.com.
level
The heading rank. Level 1 is the main heading. toHaveText waits until that heading’s text matches.
toHaveURL
Keep checking until the address matches a pattern. /iana\.org/ means the address contains iana.org. The backslash makes the dot a plain dot.
expected
The text the check asked for. In the practice box it is Example Domain.
received
The text the page actually showed. The practice box starts with other words.

The steps, before any program

  1. Open example.com.
  2. Check that the main heading says Example Domain.
  3. Click the link named Learn more.
  4. Check that the new address contains iana.org.

The program only writes those steps down.

The same steps, written as a program

Read the steps once more. The box below is those same steps. If a step fails, the result names that step and shows the text it found.

What each line is saying

  1. await page.goto("https://example.com");Open example.com. If this step fails, the problem is the address or the connection.
  2. const heading = page.getByRole("heading", { level: 1 });Name the main heading. The page is read later, when you check or click.
  3. await expect(heading).toHaveText("Example Domain");Check that the heading’s whole text is Example Domain. A failure shows the text the page had.
  4. await page.getByRole("link", { name: "Learn more" }).click();Click the link named Learn more. The click waits until that link is ready.
  5. await expect(page).toHaveURL(/iana\.org/);Check that the address contains iana.org. A different page fails here with the address you reached.

These commands help you look when the two lines are not enough.

call log
The list of actions printed with a failed check.
npx playwright test --debug
Runs the test and pauses, so you can step through it.
npx playwright test --ui
Opens a window where you can watch the test and move through its steps.
npx playwright show-report
Opens the last HTML report, a page of results from the run.
test.only
A temporary mark that runs one test and skips the rest. Remove it when you finish.

Try it

Press Run the check and read the two lines. Change the received text to Example Domain, then run the check again.

Practice. Expected is Example Domain. Change the received text and run again.

Easy to mix up

  • The output names the step that failed. Read that step before you change the test.
  • Change one thing, then run the check again.
  • A mark that runs only one test skips the rest. Remove that mark when you finish.

Remember

Read the expected text and the received text before you change the test. Change one thing, then run the check again.
