Your first test

One idea. A test opens a page and expects one fact.

The idea

A test is a function with a name and an opinion. The name says what should be true. The body makes that true-or-false observable. npx playwright test finds files named like tests/*.spec.js, runs each test, and prints a summary.

Run one file with npx playwright test tests/example.spec.js. Run one test by its name with npx playwright test -g "title". The -g flag filters by title.

Why it matters

This is the unit you will repeat. Everything else (locators, forms, traces) plugs into this shape. Once the command feels ordinary, the rest is vocabulary.

A picture to hold

A checklist item with a pencil. The string inside test is the item. expect is the pencil mark. The runner reads the whole checklist and tells you which marks are missing.

A small example

Line by line

  1. import { test, expect } from "@playwright/test";Bring in the two functions the runner wants you to use. test declares. expect checks.
  2. test("example.com names itself in the title", async ({ page }) => {The title should read like a statement of fact. Future failures quote this sentence.
  3. await page.goto("https://example.com");Open the address and wait for the load event. The load event means the document and its immediate resources have finished.
  4. await expect(page).toHaveTitle("Example Domain");Retry until the page title matches, or until the timeout. The default timeout is enough for this site.

Try it yourself

Run the check. Then type Wrong and run it again so you can see a failure. Put Example Domain back.

Demo. The page title really is Example Domain.

Common mistakes

  • Giving tests names like test 1. The report is unreadable. Name the fact you care about.
  • Forgetting async. await inside a non-async test is a syntax error.
  • Sharing one page across tests by hand. The runner gives each test a fresh page. Let it.

Recap

A test opens a page and expects a fact. npx playwright test runs the files in tests. Name tests after the fact they check.
