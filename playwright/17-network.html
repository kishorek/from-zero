Network routing

One idea. You can answer a request yourself so the page can be practiced without the real server.

The idea

A page asks its server for data. page.route(pattern, handler) intercepts requests whose URL matches the pattern. route.fulfill answers without the network, with a status, headers, and a body you supply. route.continue sends the request onward. route.abort fails it.

Call page.route before the navigation or the click that triggers the request. As with popups, the listener has to be ready early. Fulfill with JSON when the page expects JSON, and set contentType to application/json.

Why it matters

You can test “what does the page do when the server returns an empty list” without standing up that server. You can also force an error and see the message. This is a test double for the network: a stand-in that answers the way you choose.

A picture to hold

A receptionist who intercepts one kind of letter. Most letters go to the post office (continue). Letters addressed to /api/tasks get an answer you wrote (fulfill). The people upstairs still think the post office replied.

A small example

Line by line

  1. await page.route("**/api/tasks", async (route) => {** matches any host. The rest must end in /api/tasks. The handler receives the route.
  2. await route.fulfill({Answer here. The real server is not contacted for this match.
  3. body: JSON.stringify([{ title: "Buy milk" }]),The body is a string. JSON.stringify makes the string. The page will parse it.
  4. fetch("/api/tasks")This fetch runs inside the page. Playwright sees it and fulfills it because the route was armed first.
  5. await expect(page.getByText("Buy milk")).toBeVisible();Assert what the person sees after the page used the data. Do not assert only that fulfill was called.

Try it yourself

Switch the server between 200 and 500. Read the sentence the page shows.

Demo. The page believes the answer came from the server.

Common mistakes

  • Routing after goto, when the request already happened during goto. Arm the route first.
  • Fulfilling with a JavaScript object as body. The body is text. Stringify JSON.
  • Swallowing every request. A pattern that is too wide fulfills images and documents the page needed. Match the API path.

Recap

page.route intercepts matching requests. fulfill answers, continue forwards, abort fails. Register the route before the page makes the request.
