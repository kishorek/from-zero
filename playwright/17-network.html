Layer 03 · Lesson 17 of 20

Network routing

One idea. Answer the page’s data request yourself, then check what the page shows.

Start with a normal day

Luis opens his task page. The page asks another computer for the list of tasks.

A stand-in answers with one task, Buy milk, and the page shows that line.

New words

import, test, expect, await, and page mean the same as before.

page.route
A rule that catches requests whose address matches a pattern. ** stands in for any website. route is one caught request.
fulfill
Send a reply you wrote. status: 200 means the request worked. 500 means the server hit a problem. The practice menu can choose either number.
JSON
Text that stores a list of facts. contentType: "application/json" labels the reply as that text. JSON.stringify turns the list into the reply body. [0] is the first item. Counting starts at zero.
setContent
Replace the tab with a small page. That page calls fetch to ask for /api/tasks, then writes the first task into the page.
getByText
Find the words a person can read. toBeVisible keeps checking until those words are on the screen.

The steps, before any program

  1. Get ready to answer requests for the tasks list.
  2. Answer with one task named Buy milk.
  3. Open a page that asks for that list.
  4. Check that the page shows Buy milk.

The program only writes those steps down.

The same steps, written as a program

Read the steps once more. The box below is those same steps. The reply is prepared before the page asks for tasks.

What each line is saying

  1. await page.route("**/api/tasks", async (route) => {Catch any request whose address ends in /api/tasks. The arrow is the function that will answer it.
  2. status: 200,This number says the reply worked.
  3. contentType: "application/json",This label says the reply is JSON text.
  4. body: JSON.stringify([{ title: "Buy milk" }]),The reply is a list with one task, Buy milk. stringify turns that list into text.
  5. fetch("/api/tasks")The page asks for /api/tasks. The catch from the first line answers that ask.
  6. await expect(page.getByText("Buy milk")).toBeVisible();Check that the page shows the words Buy milk. Those are the words a person would read.

Try it

The page starts on the 200 answer. Switch the menu to 500 and read the new sentence.

Practice. Choose an answer. Read the sentence the page shows.

Easy to mix up

  • Set up the route before the page asks. A later rule misses a request that already happened.
  • The body is text. JSON.stringify turns the list into that text.
  • The check looks for the words Buy milk on the page. Those words are what a person sees.

Remember

page.route catches a matching request, and fulfill sends your reply. Set the route before the page asks, then check the words on the page.
