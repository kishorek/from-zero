Configuration, projects, and hooks

The idea

playwright.config.js exports defineConfig({ ... }). testDir says where tests live. use holds defaults: baseURL, traces, screenshots. With baseURL set, page.goto("/") opens baseURL + "/".

A project is a named bundle of settings, usually a browser. The starter’s projects array runs your tests in each browser you leave in the list. While you learn, one project, Chromium, is enough. Add Firefox and WebKit when you want that coverage.

test.beforeEach runs before every test in the file. Put shared navigation there. test.afterEach runs after, even when the test failed. Keep hooks short. A hook that hides a complicated login is harder to debug than a helper with a name.

Why it matters

Without a config, every test repeats the browser, the URL, and the trace policy. The config is the one place those decisions live. Hooks are for repetition inside a file. The config is for repetition across files.

A picture to hold

House rules posted at the door, versus a habit you repeat in one room. The config is the house rules: shoes off, the trace camera policy, which doors (browsers) exist. beforeEach is the habit of opening the same curtain before each task in one room.

A small example

Line by line

  1. export default defineConfig({The runner loads this file and reads the object. defineConfig gives you completion in editors that understand it.
  2. fullyParallel: true,Tests in a file may run at the same time, in separate contexts. Write tests that do not depend on each other’s order.
  3. retries: process.env.CI ? 2 : 0,Locally, fail once so you notice. In CI, where CI is set in the environment, retry twice to separate a blip from a real failure.
  4. baseURL: "https://example.com",A prefix for relative goto calls. The test uses "/" and lands on the site.
  5. { name: "chromium", use: { ...devices["Desktop Chrome"] } },One project, with a desktop Chrome viewport and user agent from Playwright’s device list. The three dots copy those settings into use.
  6. test.beforeEach(async ({ page }) => {Run this before each test in the file. The test body can assume the page is already on /.

Try it yourself

Put the config in your lab and shorten a previous test to goto("/"). Run npx playwright test --project=chromium. Add a second test to home.spec.js and confirm the hook runs for both: the heading assertion should pass without its own goto.

Common mistakes

  • Depending on test order. Parallel projects and workers will break that dependency on a different day.
  • Setting baseURL and also pasting the full URL, then “fixing” the wrong one later. Pick the config as the source of the origin.
  • Hiding a failure in afterEach by catching every error. Let the test fail. Use the hook for cleanup, not for silence.

Recap

defineConfig holds the directory, retries, reporter, traces, base URL, and projects. beforeEach shares small setup inside a file. Tests should still pass in any order.
