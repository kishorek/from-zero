Configuration, projects, and hooks

One idea. Shared settings live in one file, and a small setup step can run before every test.

Start with a normal day

Every morning Ben opens the same website and reads the heading. The house rules already name the site and the browser.

A small habit opens the home page before each check.

New words

import, test, expect, async, await, page, and getByRole mean the same as in the earlier lessons.

playwright.config.js
The file of shared settings. defineConfig wraps those settings so the runner can read them. export default hands that bundle out as the file’s main result.
testDir
The folder of tests. Here it is ./tests.
fullyParallel
true lets tests in one file run at the same time.
retries
How many extra runs a failed test gets. process.env.CI is a note a build server sets. On your machine it is usually empty, so the number of retries is 0. On that server it is 2. ? : is that short choice.
reporter
Where results are written. html means a page of results you can open.
use
Defaults every test starts with. baseURL is the site address. A test that opens / starts from there.
trace
A saved recording of the steps, the page, and the requests. on-first-retry records one when a failed test runs again.
screenshot
A picture of the page. only-on-failure takes it when a test fails.
project
One named setup, here called chromium. devices["Desktop Chrome"] is a ready-made desktop window and Chrome’s browser name. ... copies every setting from that setup.
beforeEach
A function that runs before every test in the file. Here it opens the home page.

The steps, before any program

  1. Put the shared rules in one file: the tests folder, the site, and desktop Chrome.
  2. Retry failed tests on a build server, and keep a picture when a test fails.
  3. Before each test, open the home page.
  4. Check that the heading Example Domain is visible.

The program only writes those steps down.

The same steps, written as a program

Read the steps once more. The two boxes below write those steps down. The first box is the shared settings. The second box opens the home page before each test.

What each line is saying

  1. export default defineConfig({Hand these shared settings to Playwright. defineConfig wraps them.
  2. testDir: "./tests",Look in the tests folder for the test files.
  3. fullyParallel: true,Tests in one file may run at the same time. Write each test so it can pass on its own.
  4. retries: process.env.CI ? 2 : 0,On a build server, a failed test runs two more times. On your machine, retries is 0.
  5. baseURL: "https://example.com",This is the site address. A test that opens the home page starts here.
  6. trace: "on-first-retry",Record a trace when a failed test runs again.
  7. screenshot: "only-on-failure",Take a picture when a test fails.
  8. { name: "chromium", use: { ...devices["Desktop Chrome"] } },Run the tests in desktop Chrome. The three dots copy that device’s settings.
  9. test.beforeEach(async ({ page }) => {Run the next line before every test in the file. async means this step can pause.
  10. await page.goto("/");Open the home page. The config places https://example.com in front of the slash.
  11. await expect(page.getByRole("heading", { name: "Example Domain" })).toBeVisible();Check that the heading Example Domain is on the screen. The check keeps looking until it is.

Try it

Leave the box checked and run either test. Clear the box and run one test again.

Practice. The checked box opens the home page before each test.

Easy to mix up

  • Tests may run at the same time. Each test should pass on its own.
  • The site address lives in baseURL. The test opens the home page and lands on that site.
  • Let a failed test stay failed. The failure message is the clue you need.

Remember

The config file holds the folder, the site, the browser, and the picture rules. beforeEach opens the home page before each test in the file.
