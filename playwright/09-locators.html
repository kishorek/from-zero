Locators

The idea

A locator is a description of an element, rechecked every time you use it. It is not a snapshot of the element from five seconds ago. page.getByRole("heading", { name: "Example Domain" }) means “the heading whose accessible name is Example Domain.”

The accessible name is the name assistive technology would announce. For a heading or a link, it is usually the visible text. For an input, it is usually its label.

Prefer this order: getByRole, getByLabel, getByPlaceholder, getByText, getByAltText, getByTitle, getByTestId. CSS and XPath through page.locator still work, and they break when the layout markup changes. Use them when no user-facing description exists, and prefer a stable data-testid over a CSS path when you control the page.

Why it matters

Tests that depend on div > div > span:nth-child(2) fail whenever someone wraps the span. Tests that depend on “the button named Save” fail when the button stops being Save, which is the failure you actually wanted.

A picture to hold

Asking a stranger for “the door labeled Exit” instead of “the third rectangle from the left.” The building can be repainted. The job of the door and the word on it are what a person uses. Roles are jobs: button, link, heading, textbox, checkbox.

A small example

Line by line

  1. page.getByRole("heading", { name: "Example Domain" })Role heading matches h1 through h6. name is the accessible name. You can add { level: 1 } when you care that it is an h1.
  2. page.getByRole("link", { name: "Learn more" })Role link matches an anchor a person can follow. The name is its text.
  3. await expect(heading).toBeVisible();Visible means a person could see it: it is on screen, not hidden. The expectation retries.
  4. toHaveAttribute("href", /iana\.org/)Read the href attribute and match the pattern. The backslash makes the dot a literal dot inside the pattern.

Try it yourself

On example.com, locate the heading by level as well as name. Then deliberately use the wrong name, "Example", and read the failure. Playwright lists what it did find. Put the correct name back. That error text is part of the tool.

Common mistakes

  • Starting with CSS because it feels precise. It is precise about structure, which is the brittle part.
  • Saving a located element with old APIs such as page.$ and reusing the handle later. A locator re-finds. A handle goes stale.
  • Matching a name that includes hidden text you did not know about. The accessible name can include text from a label. Read the failure’s suggestion.

Recap

Locators describe an element by role and name, and they re-find it on every use. Prefer getByRole and getByLabel. Leave CSS for last.
