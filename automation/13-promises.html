Promises

One idea. A promise is a ticket for a later answer. The line under the call still runs first.

Start with a normal day

You leave a coat at the coat check. They hand you a ticket. You do not hold the coat yet.

You start the next errand on this block. You do not wait at the counter. Later the ticket becomes the coat, or an apology if the coat is lost.

New words

The ticket has names. The program below uses them for a kettle. The line under the call still runs before the later “Tea is ready” line.

promise
A ticket for an answer that is not here yet. It will fulfill with a value, or reject with an error.
fulfill
The promise finishes with a value. In the program, resolve does this.
reject
The promise finishes with an error instead of a value.
then
What to do when the promise fulfills. That step runs after the lines under the call.
catch
What to do when the promise rejects.
arrow
=> is a short way to write a function.
Error
An object that carries a message about what went wrong. new Error("Kettle is off") builds one.

The steps, before any program

  1. Start the kettle, and take a ticket instead of the tea.
  2. If the kettle is off, the ticket fails with an error.
  3. If the kettle is on, the ticket succeeds with “Tea is ready”.
  4. Plan to print that message when the ticket succeeds.
  5. On this same stretch, say that the kettle has started.

The ticket may already be ready. You still finish the line you are on. “Tea is ready” prints after “Kettle started”.

The same steps, written as a program

Read the five steps again. The box is one file. It takes the ticket, plans the later print, and still prints “Kettle started” first.

What you should see
Kettle started
Tea is ready

What each line is saying

  1. return new Promise((resolve, reject) => {Hand back a ticket. Call resolve when the work succeeds. Call reject when it fails. The arrow is a short function.
  2. reject(new Error("Kettle is off"));Build an error with that message, and reject the promise with it.
  3. resolve("Tea is ready");Fulfill the promise with those words. The later print still waits its turn.
  4. pourTea().then((message) => {Plan the step that prints the message. The message will be “Tea is ready”.
  5. console.log("Kettle started");This is the line under the call. It still runs before the later “Tea is ready” line.

Try it

Run the box. “Kettle started” prints before “Tea is ready”. The line under the call still runs first. Then set kettleOn to false and keep the catch. You should see “Kettle is off”.

Practice. The line under the call still runs before Tea is ready.

Easy to mix up

  • The line under the call still runs before the later “Tea is ready” line. then does not jump ahead of it.
  • Forgetting to return the promise. The caller has nothing to wait on.
  • A rejection with no catch. The error has nowhere to go.

Remember

A promise fulfills with a value or rejects with an error. then and catch say what happens next. Those steps run after the current lines, so “Kettle started” prints before “Tea is ready”.
