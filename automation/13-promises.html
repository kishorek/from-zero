Promises

The idea

Some work does not finish on this line: reading a large file, waiting on the network, waiting on a timer. A promise is JavaScript’s IOU for that work. It will either settle by fulfilling with a value, or settle by rejecting with an error.

.then(function) registers what to do when the promise fulfills. .catch(function) registers what to do when it rejects. Even if the promise is already fulfilled, the .then function runs after the current stretch of code finishes. That ordering surprises people once, and then it explains a lot.

Why it matters

Playwright is promise-shaped from top to bottom. page.goto gives you a promise. If you do not wait for it, you will ask questions about a page that has not opened. This lesson is the idea. The next one is the spelling you will actually live in.

A picture to hold

A coat-check ticket. You do not hold the coat yet. You hold a ticket that will become a coat, or an apology if the coat is lost. .then is what you will do with the coat. The rest of your errands on this block can continue before the coat arrives. In the tiny example below, the “coat” arrives quickly, and the ticket system still makes you finish the current errand first.

Line by line

  1. return new Promise((resolve, reject) => {Create a promise. Call resolve(value) when the work succeeds. Call reject(error) when it fails.
  2. reject(new Error("Kettle is off"));new Error builds an error object with a message. Rejecting is the promise version of throwing.
  3. resolve("Tea is ready");Fulfill the promise with a string. This happens immediately in this demo. The .then callback still waits its turn.
  4. pourTea().then((message) => {Register the next step. message will be "Tea is ready".
  5. console.log("Kettle started");This line is still in the current stretch, so it prints first. Then the .then callback prints Tea is ready.

Try it yourself

Set kettleOn to false and add .catch((error) => { console.log(error.message); }) after .then. You should see Kettle started and then Kettle is off. A rejection with no .catch ends the program with an unhandled rejection. Always give a rejection somewhere to land.

Common mistakes

  • Expecting .then to run before the lines under it. The callback is scheduled after the current stretch.
  • Forgetting to return the promise from a function. The caller then has nothing to wait on.
  • Writing long chains of .then inside .then. It works, and it is hard to read. The next lesson replaces that shape with await.

Recap

A promise fulfills with a value or rejects with an error. .then and .catch register what happens next. Those callbacks run after the current code finishes.
