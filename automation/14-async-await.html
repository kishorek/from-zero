async and await

The idea

async marks a function that returns a promise. Inside it, await pauses that function until a promise fulfills, then continues with the value. If the promise rejects, await throws, and a try / catch in that function can handle it.

await pauses the function, not the whole computer. Other work can run. In a short script, you mostly notice that the lines below await happen in the order you wrote, which is the order you meant.

Why it matters

This is the spelling of every Playwright test: async ({ page }) => { await page.goto(url); }. If await is fuzzy, those tests will look like superstition. They are functions waiting for promises.

A picture to hold

A cook who puts the kettle on and stands at that station until it sings, instead of leaving a sticky note (.then) about what to do when it sings. The rest of the kitchen can still move. This cook’s recipe card is paused on the kettle line.

What you should see
start
after the wait

About a fifth of a second passes between the lines. setTimeout is a timer that exists in Node.js, not only in browsers. You will not sprinkle timers through Playwright tests. Real waits come from locators. This timer only makes await visible.

Line by line

  1. function delay(ms) {A helper that returns a promise. The promise fulfills after ms milliseconds. It fulfills with no useful value. Waiting is the point.
  2. setTimeout(resolve, ms);Ask the runtime to call resolve later. Calling resolve fulfills the promise.
  3. async function main() {This function always returns a promise. Callers can await main() too.
  4. await delay(200);Pause main until the delay fulfills. The next line does not run before that.
  5. main();Start the function. Without this call, nothing happens. An async function you forget to call is a recipe nobody started.

Try it yourself

Add a third log after a second await delay(200). Then wrap await delay in try / catch and reject on purpose: change delay so it returns Promise.reject(new Error("no kettle")). The catch should print no kettle, and the program should set process.exitCode = 1.

Common mistakes

  • Using await in a function that is not async. The engine reports a syntax error.
  • Forgetting to call the async function, or forgetting to await it at the top. The script can exit before the work finishes.
  • Sprinkling await delay(1000) into tests to “be safe.” That hides races. Wait for the thing you actually need.

Recap

async functions return promises. await pauses that function until the promise fulfills. A rejection becomes a throw you can catch.
