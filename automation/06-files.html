Reading and writing files

One idea. A file remembers text after the program stops.

Start with a normal day

You write a shopping note and close the notebook. You leave the room. The words in your head are gone. The notebook is still on the desk.

A program is the same. Names it created disappear when it stops. A file does not.

New words

import, const, and console.log are the same tools as before. This lesson adds files.

node:fs
Node’s file tools. The curly braces in import { readFileSync, writeFileSync } pull in those two names.
Sync
The line waits until the disk is finished before the next line runs.
writeFileSync
Store text in a file. It creates the file, or replaces what was there.
readFileSync
Read a file and hand back the text.
appendFileSync
Add text at the end of a file. The practice box calls this appendFile.
utf8
Read the file as ordinary text. Without it you get a buffer, a bag of raw bytes, which is the wrong tool for a note.
new URL
Build a file address. import.meta.url is the address of this script. "./note.txt" means the note in the same folder.
\n
One new line. After milk, the next words start on the following line.
readFile / writeFile
In the practice box, these stand in for readFileSync and writeFileSync.
process.cwd()
The folder you were in when you started the program. A plain path such as note.txt starts there. The URL form follows the script instead.

The steps, before any program

  1. Bring in the two tools that read and write, and wait while they do it.
  2. Build an address for note.txt in the same folder as this script.
  3. Write “Buy milk” into that file, and replace whatever was there.
  4. Read the file back as text.
  5. Show that text.

Replacing is the usual write. Adding to the note is appendFile in the practice box. The practice names readFile and writeFile are the stand-ins for the Sync tools above.

The same steps, written as a program

Read the five steps again. This file does them in order. The write waits for the disk before the read starts. You run it with node note.mjs.

What you should see
Buy milk

What each line is saying

  1. import { readFileSync, writeFileSync } from "node:fs";Bring in two tools by name. Curly braces mean these names, not the whole module.
  2. const file = new URL("./note.txt", import.meta.url);Point at a note beside this script. The name file holds that address, not the note itself. ./ means in the same folder as this file.
  3. writeFileSync(file, "Buy milk\n");Save one line into the note, replacing the old text. \n is one newline character. Replacing is the default. appendFileSync adds instead.
  4. const text = readFileSync(file, "utf8");Read the note back as text. The name text holds that note. Without utf8, you get a buffer of bytes, which is the wrong tool for a note.
  5. console.log(text);Show the note. The newline makes the next line start after milk.

Try it

Run once. The note is written, then read back. Change writeFile to appendFile, press Run twice, and watch the note grow. Reset starts the file over.

Practice. writeFile replaces the note. appendFile adds to it. Each Run continues from the file box.

Easy to mix up

  • Passing a folder to readFileSync. Reading a folder stops with an error. Read a file path.
  • Forgetting utf8 and then calling string methods on a buffer.
  • Using a path like note.txt and expecting it to sit beside the script no matter where you launched node. A plain relative path is relative to process.cwd(). The URL form above follows the script.

Remember

writeFileSync stores text. readFileSync reads it back as utf8. A path built from import.meta.url stays next to the script.
