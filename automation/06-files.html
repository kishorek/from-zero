Reading and writing files

The idea

A file on disk outlives the program. writeFileSync stores text. readFileSync reads it back. Both come from node:fs. The Sync in the name means this line waits for the disk before the next line runs. That is a clear model while the files are small.

Later, async and await will show the non-blocking versions, readFile and writeFile from node:fs/promises. Playwright uses that waiting style. The ideas are the same: a path, the text, and the encoding.

Why it matters

Reports, downloaded data, and Playwright’s storageState are all files. If you can write a note and read it back, those features are the same motion with a fancier path.

A picture to hold

A notebook you close when you leave the room. Variables forget everything when the program ends. The notebook is still on the desk. writeFileSync is closing the notebook. readFileSync is opening it tomorrow.

A small example

What you should see
Buy milk

Line by line

  1. import { readFileSync, writeFileSync } from "node:fs";Bring in two functions. Curly braces mean “these names, not the whole module.”
  2. const file = new URL("./note.txt", import.meta.url);Build a file address next to this script. ./ means “in the same folder as this file.”
  3. writeFileSync(file, "Buy milk\n");Create or replace note.txt with that text. \n is one newline character. Replacing is the default. There is also appendFileSync when you want to add.
  4. const text = readFileSync(file, "utf8");Read the bytes and decode them as text. Without utf8, you get a buffer of bytes, which is the wrong tool for a note.
  5. console.log(text);Print the note. The newline makes the shell move to the next line after milk.

Try it yourself

Write two lines into note.txt, read them back, and print them. Then run the script twice and open the file. It still holds only the latest write, because writeFileSync replaces. Switch the write to appendFileSync and run twice. The file should grow.

Common mistakes

  • Passing a folder to readFileSync. Reading a folder throws. Read a file path.
  • Forgetting utf8 and then calling string methods on a buffer.
  • Using a path like note.txt and expecting it to sit beside the script no matter where you launched node. A plain relative path is relative to process.cwd(). The URL form above follows the script.

Recap

writeFileSync stores text. readFileSync reads it back as utf8. A path built from import.meta.url stays next to the script.
