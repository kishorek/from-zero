Logs and exit codes

One idea. People read the message. The shell reads the exit code.

The idea

console.log is for ordinary progress. console.error is for failures. They are both just streams of text. By convention, error text goes to standard error, a second channel the shell can separate from normal output.

The exit code is the program’s official result. Use 0 when the job worked and 1 when it did not. Set process.exitCode. Let the function return. The process ends, and the code goes with it.

Why it matters

A Playwright run prints a lot and also exits 0 or 1. Scripts you write will sit inside other scripts. Those callers cannot read your prose. They can read the exit code. Give them a reliable one, and give humans a sentence.

A picture to hold

A reception desk with two trays and a lamp. The trays are the two output streams: notes, and problems. The lamp is the exit code: green or red. People read the trays. The next machine only looks at the lamp.

A small example

Line by line

  1. const name = process.argv[2];The input, from the command, as in the arguments lesson.
  2. console.error("Missing name.");A failure sentence on the error stream. Keep it short and specific.
  3. process.exitCode = 1;Tell the shell this run failed. Do not also call process.exit unless you have a reason to halt immediately.
  4. console.log("Hello, " + name);Ordinary output. This is the result a person wanted.
  5. process.exitCode = 0;Explicit success. Ending with no assignment also exits 0. Setting it makes the success look as deliberate as the failure.

Try it yourself

Run with a name, then clear the words and run again. A missing name should exit 1. A one-letter name should exit 1 too.

Practice. Al is long enough. A is not.

Common mistakes

  • Printing Success and exiting 1, or printing an error and exiting 0. The lamp and the tray disagree, and callers believe the lamp.
  • Using console.log for every failure. When someone redirects normal output to a file, the failures vanish into the file too.
  • Calling process.exit(1) inside a function that another file imported. You just closed their whole program. Throw, or return a result, and let the top of the script set the exit code.

Recap

console.log for results, console.error for problems, process.exitCode for the shell. Humans read the text. Other programs read the code.
