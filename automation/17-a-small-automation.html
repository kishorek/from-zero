A script that turns a list into a report

One idea. Read a list, skip blanks and comments, write a numbered report.

The idea

This script is the layer in one file. It reads tasks.txt from the script’s folder, drops blank lines and comments, numbers what remains, and writes report.txt with today’s date. If the source file is missing, it prints an error and exits 1.

The rules live in functions. The reading and writing sit in main. That split is what you will keep doing: pure decisions in one place, effects (files, network, browsers) at the edge.

Why it matters

You can now automate a boring tidy-up without a browser. Layer 3 adds the browser. The shape does not change. Read input, decide, write output, report failure with a code.

A picture to hold

A night clerk. The inbox is tasks.txt. The clerk discards blank slips and slips that start with #, numbers the rest, dates the packet, and files it as report.txt. If the inbox was never delivered, the clerk turns on the red lamp and writes nothing.

A small example

Create tasks.txt beside the script first. Lines starting with # are comments. Then run node report.mjs.

What you should see
Wrote 2 tasks.

Line by line

  1. function visibleTasks(raw) {Turn file text into the lines worth keeping. No files are touched in here. That makes the rule easy to trust.
  2. .filter((line) => line.length > 0 && !line.startsWith("#"));Keep a line when it has characters and does not start with #. && means both tests must pass. startsWith is a string question.
  3. function reportText(tasks) {Build the report as a string. Writing the file is someone else’s job.
  4. tasks.forEach((task, index) => lines.push(`${index + 1}. ${task}`));forEach runs a function for each item and does not build a new array. Pushing onto lines is the effect we want.
  5. raw = readFileSync(source, "utf8");Read the inbox. A missing file throws. The catch turns that into a sentence and exit code 1.
  6. writeFileSync(target, reportText(tasks));Replace report.txt with the new report. Open that file and check the date and the numbering.

Try it yourself

Run the box. Comments and blank lines are skipped. Add a third task in the file and run again. The report should number three tasks.

Practice. Lines that start with # are notes, not tasks.

Common mistakes

  • Catching the read error and still writing an empty report. You just destroyed yesterday’s report because today’s inbox was missing.
  • Numbering comment lines. Filter first, then number.
  • Putting the date format, the filter, and the file write in one long block. When it breaks, you cannot tell which job failed.

Recap

A practical script reads input, cleans it with ordinary JavaScript, writes an output, and sets an exit code when the input is missing. The next layer points this same discipline at a browser.
