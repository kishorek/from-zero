Command-line arguments

The idea

Arguments are extra words on the command. In node greet.mjs Ada, the word Ada is an argument. Node.js stores the whole command in process.argv, an array of strings.

Index 0 is the path to node. Index 1 is the path to your script. Your first real argument is index 2.

Why it matters

A useful script does not hide its input inside the file. You pass the file name, the city, or the URL on the command, so tomorrow you can run the same file on different input.

A picture to hold

A food-truck window. The script is the kitchen. The words after the script name are the order shouted at the window. The kitchen does not rewrite the menu for each customer. It reads the order.

A small example

What you should see
Hello, Ada.

Run it with no extra word and the usage line appears, with exit code 1. The ! means “not.” !name is true when name is missing.

Line by line

  1. const name = process.argv[2];Read the first word you added after the script name. If you did not add one, name is undefined.
  2. if (!name) {Missing argument. Say how to run the script, and mark the exit code as a failure.
  3. console.log("Usage: node greet.mjs <name>");A usage line is a tiny manual. Angle brackets mean “put a value here.” You do not type the brackets.
  4. console.log(`Hello, ${name}.`);The argument was present. Build a sentence with it.

Try it yourself

Extend the script so the second argument is a city: node greet.mjs Ada Lagos prints Hello, Ada from Lagos. Use process.argv[3]. If either word is missing, print the usage line and set the exit code.

Common mistakes

  • Reading process.argv[0] and expecting your name. That slot is Node.js itself.
  • Forgetting that every argument arrives as text. The number 3 arrives as "3" until you convert it with Number.
  • Putting the value in the file and also requiring it as an argument, so you have two sources and they drift apart.

Recap

process.argv is the command, split into words. Your first argument is index 2. Check that it exists before you use it.
