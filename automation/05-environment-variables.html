Environment variables

One idea. A setting can live outside the file. The file only knows the name.

Start with a normal day

You hand a coat to a cloakroom and keep a ticket with a name on it. The coat stays in the cloakroom.

A setting works the same way. The file knows the name, such as API_KEY. The value stays outside the file. A password written in the file travels with anyone who copies the file.

New words

const, if, else, and console.log are the same tools as in the first layer.

environment variable
A named setting that lives outside the file. The file knows the name. The surroundings hold the value.
process.env
The group of those settings for this run. process.env.API_KEY reads the one named API_KEY. A missing name is undefined.
secret
A password, or a token that stands in for one. It does not belong in the program file. A log is text people copy into bug reports, so the log should not contain the secret.
.env
A text file of settings. Each line is a name, an equals sign, and a value. That line is not JavaScript.
.env.example
A file you may share. It lists the names and leaves the values blank.
commit
Save a file into the shared history of the project. Share .env.example. Keep .env on your machine.
--env-file
An option on the node command. Node.js 20 or newer reads that file before the program starts. Node does not load .env unless you ask.
!
Means “not.” !key is true when key is missing.
process.exitCode
The final number for the terminal. 1 means something was wrong.
length
How many characters are in the text. Printing the length shows that a secret arrived, without printing the secret.

The steps, before any program

  1. Write one line in a file named .env. The name is API_KEY. The value is replace-me.
  2. Start the program with node --env-file=.env app.mjs, so the settings load first.
  3. Ask the environment for API_KEY.
  4. If nothing is there, say it is missing and mark the run as failed. Do not invent a password inside the file.
  5. If a value is there, say the setting is set and show how many characters it has. Do not show the value.

The file only asks for a name. Node.js 20 or newer understands --env-file. It will not load .env unless you ask. The value replace-me has 10 characters. You should see that length, not the secret.

The same steps, written as a program

Read the five steps again. The first box is the settings file. It is not JavaScript. The caption on the second box is how you start the program. The code only looks up the name.

What you should see

What each line is saying

  1. API_KEY=replace-mePut one setting on one line. The name comes first, then an equals sign, then the value. This line is not JavaScript. The --env-file flag reads it before the program starts.
  2. const key = process.env.API_KEY;Look up API_KEY and keep what comes back. If the name was not set, key is undefined.
  3. if (!key) {Ask whether that value is missing. The ! means not. A missing value takes this path.
  4. console.log("Missing API_KEY. Set it in the environment.");Tell the reader what to fix. Do not invent a fallback password inside the file.
  5. process.exitCode = 1;Mark this run as failed. The number 1 means something was wrong.
  6. } else {Take this path when a value was there.
  7. console.log("API_KEY is set. Length:", key.length);Show that the value arrived, without showing the value. The length is enough evidence while you learn. replace-me is 10 characters long.

Try it

Run with CITY=Lisbon. Then erase that line and run again. The script should say the city is missing.

Practice. The box reads the settings above. It does not hide a city inside the code.

Easy to mix up

  • Printing the secret “just to check.” Logs get copied into bug reports.
  • Committing .env. Commit a .env.example that lists the names with blank values.
  • Expecting Node.js to load .env by itself. You opt in with --env-file, or with a tool you installed on purpose.

Remember

process.env holds named settings from outside the file. Keep secrets there. Print that a secret exists, not what it is.
