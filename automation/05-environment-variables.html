Environment variables

One idea. A setting can live outside the file. The file only knows the name.

The idea

An environment variable is a named setting that lives outside your file, in the environment of the process. process.env is an object of those settings. process.env.API_KEY reads the one named API_KEY.

Secrets (passwords, tokens) do not belong in source code. Anyone who receives the file would receive the secret. Put them in the environment. Node.js 20 and newer can load a file of settings when you start the program: node --env-file=.env app.mjs. The file is named .env by convention. Do not commit that file.

Why it matters

Playwright projects use the environment for CI secrets, base URLs, and passwords. The habit starts here: code asks for a name, the environment supplies the value, logs never print the value.

A picture to hold

A coat check. The script knows the ticket name (API_KEY). The cloakroom (the environment) holds the coat. You can hand the same script to someone else with an empty cloakroom, and it will say the coat is missing instead of smuggling your coat in the script.

A small example

What you should see
API_KEY is set. Length: 10

Line by line

  1. API_KEY=replace-meOne setting per line, name then equals then value. This is not JavaScript. The --env-file flag reads it before your script starts.
  2. const key = process.env.API_KEY;Look up that name. If it was not set, key is undefined.
  3. console.log("Missing API_KEY. Set it in the environment.");Tell the reader what to fix. Do not invent a fallback password inside the file.
  4. console.log("API_KEY is set. Length:", key.length);Prove the value arrived without printing it. Length is enough evidence while you learn.

Try it yourself

Run with CITY=Lisbon. Then erase that line and run again. The script should say the city is missing.

Practice. The box reads the settings above. It does not hide a city inside the code.

Common mistakes

  • Printing the secret “just to check.” Logs get copied into bug reports.
  • Committing .env. Commit a .env.example that lists the names with blank values.
  • Expecting Node.js to load .env by itself. You opt in with --env-file, or with a tool you installed on purpose.

Recap

process.env holds named settings from outside the file. Keep secrets there. Print that a secret exists, not what it is.
