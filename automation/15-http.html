HTTP requests with fetch

One idea. fetch gets an answer. A missing page is still an answer. Check response.ok.

Start with a normal day

You phone a shop and ask for a book. A person answers. They may have it. They may not. Both times, someone answered.

If the call never connects, nobody answered. A script has the same split. “Not found” is an answer. Silence is not.

New words

if, !, async, await, .catch, and process.exitCode mean the same as before.

HTTP
The rules one computer uses to ask another for a page.
fetch
Ask for an address. The answer is a response.
status
The number on that answer. 200 means the page was found. 404 means there is no such page.
ok
response.ok is true when the status is 200 through 299. !response.ok is true for a 404.
body
The page that came with the answer. response.text() reads it. slice(0, 80) keeps the first 80 characters.
throw
Stop because of a problem. catch receives it. error.message is the short sentence. console.error prints that sentence apart from ordinary notes.

The steps, before any program

  1. Ask example.com for its page.
  2. Read the status number.
  3. If the status is not ok, stop and report that number.
  4. Read the page as text.
  5. Print only the first 80 characters.
  6. If a problem was thrown, print the sentence and set the exit code to 1.

The same steps, written as a program

Read the six steps again. This file waits for the answer, checks the number, then prints a short piece of the page. The last lines catch a problem and set the exit code.

What each line is saying

  1. async function main() {Start a function that is allowed to wait. main is only its name.
  2. const response = await fetch("https://example.com");Ask that computer for information. Wait until the response arrives.
  3. console.log(response.status);Print the status number. For this address it is 200.
  4. if (!response.ok) {The ! means not. This path runs when ok is false. A 404 lands here.
  5. throw new Error("Request failed with status " + response.status);Stop, and send a sentence joined to the status number.
  6. const text = await response.text();Wait again. Read the body as text.
  7. console.log(text.slice(0, 80));Print the first 80 characters. The note stays short.
  8. main().catch((error) => {Run main. If it throws, catch receives the Error.
  9. console.error(error.message);Print the problem sentence.
  10. process.exitCode = 1;Set the exit code to 1. The program that started you can see that this did not finish as planned.

Try it

Run the box as it is. You should see 200. Change the address to https://example.com/missing and run again. You should see 404.

Practice. This demo knows example.com and example.com/missing only.

Easy to mix up

  • A lost connection throws. A 404 does not. The other computer did answer. You still check response.ok.
  • response.json() reads a body made of named values. This page is ordinary text. Use response.text(). The other read fails.
  • You wait once for the response and once for the body. Skip the second await and you do not have the text yet.

Remember

fetch means “ask another computer for information.” The response has a status. response.ok is true only for 200 through 299. Read the body with await response.text(). A 404 is still a response. Set the exit code when you throw.
