HTTP requests with fetch

The idea

HTTP is the language browsers and servers use to request a document. fetch(url) returns a promise of a response. The response has a status number. 200 means okay. 404 means the server has no such page.

fetch rejects when the network fails: no connection, no DNS, the request never completed. It does not reject for a 404. The server did answer. Check response.ok, which is true for statuses 200 through 299, and throw your own error when it is false.

response.text() reads the body as text. response.json() reads it as JSON. Each of those returns a promise, so you await them too. Node.js 20 includes fetch. You do not install a package for it.

Why it matters

A lot of automation never opens a browser. It asks an API for JSON. Playwright can do that too, and it can also watch the page’s own requests. Both start from this picture: request, status, body.

A picture to hold

Sending a letter and getting a numbered reply. The post office losing the letter is a rejection. A reply that says “no such person” is still a reply. You have to read the number. response.ok is you checking that the number means “here is what you asked for.”

A small example

What you should see
200
<!doctype html>\n<html>\n<head>\n    <title>Example Domain</title>...

Line by line

  1. const response = await fetch("https://example.com");Send a GET request, the default, and wait for the headers to come back.
  2. console.log(response.status);Print the status number. For this URL it is 200.
  3. if (!response.ok) {Statuses outside 200–299 land here. This is how a 404 becomes your error instead of a quiet success.
  4. const text = await response.text();Read the body. This second wait is required. The headers arrived first. The body is a separate read.
  5. console.log(text.slice(0, 80));slice takes the first 80 characters so the terminal stays readable.
  6. main().catch((error) => {The promise returned by main rejects if you throw. This catch prints the message and sets a failing exit code.

Try it yourself

Point fetch at https://example.com/missing. Print the status. You should see 404, then your thrown message, then exit code 1. After that, fetch https://example.com again and find the word Example in the text with includes.

Common mistakes

  • Treating every rejection as a 404, or treating every 404 as a rejection. They are different events.
  • Calling response.json() on a body that is HTML. Parsing throws a syntax error. Read text unless you know the body is JSON.
  • Forgetting the second await and printing a promise instead of the body.

Recap

fetch returns a response. Check response.ok and the status. await response.text() or await response.json() reads the body. Network failure rejects. A 404 does not.
