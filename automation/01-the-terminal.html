The terminal

One idea. The terminal takes one short command at a time.

The idea

The terminal is a text window onto a shell. A shell is a program that reads a command, runs it, and prints the result. You have already used node. The same window also moves you between folders.

pwd prints the folder you are in. ls lists what is there. cd somewhere enters a folder. cd .. goes up to the parent. mkdir notes creates a folder.

Why it matters

Node.js, npm, and Playwright are all driven from this window. If the shell feels like a locked door, every later command feels risky. It is a counter. You ask for one thing. It answers, then waits.

A picture to hold

A service counter in a workshop. You do not wander into the storeroom. You say “where am I,” “what is on this shelf,” or “make a new box.” The shell is the person behind the counter. Each line you type is one request.

A small example

What you should see
This script is running from:
/your/current/folder

Line by line

  1. pwdPrint working directory. The answer is a path, the address of the folder the shell is using.
  2. lsList the names in that folder. It does not enter them.
  3. mkdir notesCreate a folder named notes inside the current folder.
  4. cd notesChange the shell’s current folder to notes. Later commands, including node, start from here.
  5. console.log(process.cwd());The same fact, asked from JavaScript. cwd means current working directory. It matches pwd when you launched node from that folder.

Common mistakes

      
  • Typing a JavaScript line into the shell and a shell command into a .js file. They are different languages at the same counter.
    • 

  • Assuming cd inside one terminal window changes any other window. Each window has its own current folder.
    • 

  • Panicking at a long path. Read it from the right: the last piece is the folder you are in.

      
Recap

      
The shell reads one command at a time. pwd, ls, cd, and mkdir move you around. process.cwd() is that same folder, seen from JavaScript.
