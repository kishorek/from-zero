Errors

The idea

An error means the engine could not do a step. A SyntaxError is bad spelling, found before the program really starts. A ReferenceError means you used a name that does not exist. A TypeError means the value you have cannot do what you asked, such as reading a property of undefined.

The message includes a file and a line. That line is where to look first. try and catch let you handle an error instead of crashing. catch receives the error object. error.message is the sentence.

Why it matters

You will write errors on purpose for the rest of your life. A useful message is part of the program. “Could not read tasks.txt” is a gift. A crash with no context is a puzzle.

A picture to hold

A smoke alarm. The alarm does not repair the toast. It stops the quiet and tells you which room. try is the room you are watching. catch is what you do when the alarm sounds.

A small example

What you should see
Could not pour: Cannot read properties of undefined (reading 'volumeMl')

Line by line

  1. return cup.volumeMl;This asks for the volumeMl property of whatever cup is. If cup is undefined, there is no object to read, and JavaScript throws a TypeError.
  2. try {Start a watched block. If something inside throws, the engine jumps to catch instead of ending the whole program.
  3. console.log(pour(undefined));Call pour with no object. This is the line that throws.
  4. } catch (error) {error is the object that was thrown. It has a message property.
  5. console.log("Could not pour: " + error.message);Print your own context plus the engine’s sentence. The program then ends normally, because the error was caught.

Try it yourself

Remove the try and catch and call pour(undefined) directly. Read the stack: it names pour.js and a line. Put the try back. Then call pour({ volumeMl: 300 }) inside the try and confirm it prints 300 and does not enter catch.

Common mistakes

  • Empty catch blocks that hide the failure. If you catch, print the message or rethrow.
  • Guessing the cause before you read the line number.
  • Wrapping an entire file in try and continuing as if nothing happened. Catch the step that can fail, close to that step.

Recap

Errors name a file, a line, and a reason. try / catch handles a failure you anticipated. error.message is the sentence to show.
