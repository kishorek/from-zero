Debugging

One idea. Debugging means printing the value you are unsure about.

The idea

A bug is a difference between what you meant and what the engine did. Debugging is how you find the first line where those two diverge.

The practical method is small. Read the error. Print the values just before the bad line. Check the assumption you are least sure of. Change one thing. Run again.

The Node.js debugger (node inspect file.js) can pause on a line. You do not need it yet. console.log is enough for this course, and professionals still use it.

Why it matters

Later error messages can look noisy. The skill underneath is the same one you practice here. Find the first surprise. Change one thing, then run again.

A picture to hold

Looking for a lost key by walking your route backwards. You do not redecorate the house. You stand where you last know you had the key, then take one step.

A small example

What you should see
count 2
first boil
third undefined

steps[2] does not throw. It is simply undefined, because that mailbox is empty. A later line that treated steps[2] as an object would throw. The print shows you the gap before that happens.

Line by line

  1. const steps = ["boil", "steep"];Two items. Valid indexes are 0 and 1.
  2. console.log("count", steps.length);Print a label and a value. Labels keep you from mixing up several numbers on the screen.
  3. console.log("first", steps[0]);Confirm the first item is what you think. Here it is boil.
  4. console.log("third", steps[2]);Ask for an index that does not exist. The evidence is undefined. Your theory of “there is a third step” is the bug.

Try it yourself

Print the last item of an empty list and of ["a", "b"]. You should see undefined, then b.

Practice. Look at both results before you decide the function is right.

Common mistakes

  • Changing several lines before the next run. You will not know which change mattered.
  • Printing so much that you stop reading it. Print the one value tied to your current guess.
  • Trusting a memory of the file instead of the file. The engine ran the file, not your memory of it.

Recap

Debugging compares what you meant with what happened. Read the line. Print the nearby values. Change one thing and run again.
