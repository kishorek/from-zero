Errors

One idea. An error points at a line. try and catch let you answer it.

Start with a normal day

A smoke alarm does not fix the toast. It stops the quiet and tells you which room.

You ask to pour a cup, and you hand over nothing. There is no cup to read. The helper raises an alarm and names the problem.

You can watch that step. When the alarm sounds, you show your own sentence plus the helper’s sentence. The rest of the program can finish.

New words

Three kinds of alarm show up often. This program meets one of them on purpose.

error
The helper could not do a step. The message names a file, a line, and a reason.
SyntaxError
The spelling is wrong. The helper notices before the steps really start. A missing quote is this kind.
ReferenceError
You used a name that was never created.
TypeError
The value you have cannot do what you asked. Reading a blank on undefined is this kind. This page’s program raises one.
throw
Raise the alarm and jump out of the current step.
try
The steps you are watching.
catch
What to do when an alarm sounds inside the try. It receives the error.
error.message
The sentence on the alarm.
undefined
A missing value. It is not a form, so it has no blanks to read.

The steps, before any program

  1. Write a recipe that reads a cup’s volume.
  2. Watch one attempt to pour.
  3. Hand the recipe nothing, instead of a cup.
  4. When the alarm sounds, show “Could not pour:” and the helper’s sentence.

The practice box starts with a real cup, so you can see the calm path first.

The same steps, written as a program

Read the four steps again. try is the room you are watching. catch is what you do when the alarm sounds. The recipe asks for a blank that nothing does not have.

What you should see
Could not pour: Cannot read properties of undefined (reading 'volumeMl')

What each line is saying

  1. return cup.volumeMl;Read the volume blank of whatever cup is. If cup is undefined, there is no form to read, and the helper raises a TypeError.
  2. try {Start the watched steps. If something inside raises an alarm, the helper jumps to catch.
  3. console.log(pour(undefined));Run pour with no cup. This is the line that raises the alarm.
  4. } catch (error) {error is the alarm itself. It has a message blank.
  5. console.log("Could not pour: " + error.message);Show your own words plus the helper’s sentence. The program then ends calmly, because the alarm was answered.

Try it

Press Run first. A real cup is passed in, so you should see 300. Then change the call to pour(undefined) and run again. You should see the “Could not pour” line.

Practice. First pour a real cup. Then pass undefined and read the message.

Easy to mix up

  • An empty catch hides the alarm. If you catch, show the message.
  • Read the line number in the message before you change anything.
  • Watch the step that can fail. Wrapping the whole file makes it hard to see which step alarmed.

Remember

An error names a line and a reason. try watches a step. catch answers the alarm. error.message is the sentence to show.
