How does a computer understand instructions?

The idea

The processor inside a computer follows extremely small electrical steps. It does not read English, and it does not read JavaScript either. A translator sits between your file and the processor.

For JavaScript, that translator is an engine. Chrome and Node.js both use an engine called V8. V8 reads your file, checks the spelling, and carries out the instructions. When people say “the computer understands the code,” they mean this engine accepted it and did it.

Why it matters

Two pieces of text can look similar and mean different things, because the engine follows rules, not vibes. The example below adds numbers one way and glues text another way. Both use +. The quotes change the rule.

A picture to hold

Imagine a very literal clerk who speaks only a private shorthand. You write a letter in JavaScript. V8 is the interpreter who turns your letter into the clerk’s shorthand and reads it aloud. If your letter breaks the grammar, the interpreter stops and points at the line.

A small example

What you should see
5
23

Line by line

  1. console.log(2 + 3);There are no quotes, so 2 and 3 are numbers. Plus adds them. The engine prints 5.
  2. console.log("2" + "3");The quotes make text. Plus on text glues the pieces into a longer text. The engine prints 23, not 5.

Try it yourself

Predict the result of console.log("2" + 3) before you run it. Then run it. The number is turned into text and glued, so the line prints 23. Write one sentence about why, in a comment above the line.

Common mistakes

  • Believing the computer grasps your goal. It applies rules to the text you wrote.
  • Assuming + always means arithmetic. With text, + joins.
  • Editing random lines after an error. Read the line number in the message first. The engine is pointing.

Recap

An engine translates JavaScript into work the processor can do. V8 is that engine in Node.js and Chrome. The same symbol can follow different rules when the values differ.
