Debugging

One idea. Debugging means showing the value you are unsure about, then changing one thing.

Start with a normal day

You lost a key. You walk the route backwards. You stand where you last know you had it, then you take one step.

A bug is a gap between what you meant and what the helper did. You find the first line where those two split.

The method is small. Read the message. Show the value just before the bad line. Change one thing. Run again.

New words

This page looks for a third tea step that was never written.

bug
The program did something different from what you meant.
debugging
Gathering evidence about what the program actually did.
console.log
Show a label and a value. You can pass both, separated by a comma: console.log("count", steps.length).
index
The address of an item. Two items have addresses 0 and 1. Address 2 is empty.
undefined
The value in an empty address. Asking for it does not always raise an alarm. It quietly gives you undefined.

The steps, before any program

  1. You believe there are three tea steps.
  2. Show how many steps are actually in the list.
  3. Show the first step.
  4. Show the third step, and read what comes back.

The list only has two words. The third address is empty. Seeing that is the whole lesson.

The same steps, written as a program

Read the four steps again. Each console.log is one piece of evidence. The label in quotes tells you which number you are looking at.

What you should see
count 2
first boil
third undefined

Address 2 does not raise an alarm. It is simply empty. A later line that treated that empty value as a form would raise an alarm. The print shows the gap first.

What each line is saying

  1. const steps = ["boil", "steep"];Two items. The real addresses are 0 and 1.
  2. console.log("count", steps.length);Show a label and the count. The count is 2. The label keeps this number separate from the others.
  3. console.log("first", steps[0]);Check the first item. It is boil, which matches the list.
  4. console.log("third", steps[2]);Ask for an address that is empty. The evidence is undefined. The idea “there is a third step” is the bug.

Try it

The box asks for the last item of an empty list, then the last item of a list with a and b. You should see undefined, then b.

Practice. An empty list and a two-item list. Read both results.

Easy to mix up

  • Change one thing, then run again. Several changes at once hide which one mattered.
  • Show the one value tied to your current guess. A flood of lines is hard to read.
  • The helper ran the file. Check the file, rather than your memory of the file.

Remember

Debugging compares what you meant with what happened. Read the line. Show the nearby value. Change one thing and run again.
